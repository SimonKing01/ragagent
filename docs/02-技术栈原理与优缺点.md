# 2. 技术栈原理与优缺点

| 技术 | 在本项目的角色 | 原理简述 | 优点 | 缺点 / 注意 |
|---|---|---|---|---|
| **JDK 21 + 虚拟线程** | 运行时与并发模型 | `spring.threads.virtual.enabled=true`，一请求一虚拟线程；管线并发与工具并行用 `Thread.ofVirtual()` / `newVirtualThreadPerTaskExecutor()` | 阻塞式写法获得高并发；无需全链路响应式改造 | ThreadLocal 身份不随虚拟线程走，必须显式快照（见 [§17](17-多租户认证与RBAC.md)） |
| **Spring Boot 3.3（Spring MVC，Servlet 栈）** | Web 框架 + 依赖注入 | Tomcat + 同步 Controller；过滤器/拦截器链承载鉴权、外壳、RBAC、追踪 | 生态成熟、调试直观、与虚拟线程契合 | 长连接 SSE 占用容器线程，依赖流管理器解耦生成与输出（见 [§12](12-会话流式输出与SSE.md)） |
| **MyBatis-Plus + 手写仓储** | 数据访问 | 单表 CRUD 走 `Mapper`；跨表/方言/事务走 `Repository` | SQL 可控、方言差异集中 | 软删谓词要显式写，靠机器探测兜底（见 [§19](19-持久化与数据模型.md)） |
| **PostgreSQL 17 + pgvector（ParadeDB）** | 默认数据库与默认检索引擎 | ParadeDB 镜像提供 pgvector 与 BM25 全文检索能力 | 一库两用，dev 零额外组件 | 检索引擎 `RETRIEVE_DRIVER` 为空 = 检索关闭 |
| **Redis 7（Lettuce）** | 可选的跨实例共享面 | 流管理器、五套任务队列、wiki 锁、限流预算、模型并发闸门的双后端之一 | 多实例部署的统一协调面 | 单实例默认全走进程内；开关打开后连不上即启动失败，不静默退化 |
| **Flyway** | 数据库迁移 | `migrations/versioned/` 按序执行；镜像内迁移目录与 WORKDIR 绑定 | 存量库自动 baseline | 迁移脚本不可手改，checksum 失败要走 repair 流程 |
| **gRPC + protobuf** | 文档解析通道 | `docreader/docreader.proto` 构建期生成本地客户端，解析服务独立容器部署 | 解析重活出进程、可独立扩缩 | 需要额外容器；地址 `DOCREADER_ADDR` |
| **DuckDB JDBC** | SQL / 数据分析工具后端 | Agent 的数据表分析工具内嵌 DuckDB 执行 | 免外部数仓依赖 | 仅分析用途，不是业务库 |
| **Neo4j（Java Driver）** | 可选图数据库 | 实体-关系图谱落库与检索；`NEO4J_ENABLE` 门控 | 图谱召回补充向量/关键词 | 未启用退化 no-op；启用后连不上**启动失败** |
| **对象存储 SDK 族** | 文件存储后端 | AWS S3 兼容 / 阿里 OSS / 腾讯 COS / 火山 TOS / MinIO / 本地，按租户可选 | 私有化与云上都能落地 | 凭据 AES 加密落库；本地目录必须持久化 |
| **JJWT + spring-security-crypto** | 认证与凭据 | JWT 签发校验；BCrypt 口令；AES-GCM 凭据加密 | 标准件、无自研密码学 | `JWT_SECRET` 不固定则重启掉登录 |
| **Micrometer + Actuator** | 指标与探针 | 只暴露 `health` / `info` / `metrics` 三个端点 | Prometheus 生态直接可抓 | 指标名集中在 `ragagent.qa.*` 等少量业务维度 |
| **OTLP / Langfuse** | 链路追踪导出 | OTLP proto 随仓交付；Langfuse 装饰器未配置即 no-op | 可接自建观测台 | Langfuse 配置无效会拒启，不是降级 |
| **springdoc-openapi** | API 文档 | 默认关闭；本地 `SPRINGDOC_ENABLED=true` 后开 Scalar UI | 生产面零暴露 | 生产保持关闭 |
| **ArchUnit + 脚本守卫** | 架构决策的执行器 | 48 条守卫 + 多份 `*.baseline.json` 棘轮，CI 与本地同一入口 | 约束不靠自觉，违规即红 | 守卫本身要随架构演进同步维护 |
| **Vue 3.5 + Vite 7 + TypeScript + Pinia** | Web 控制台 | `frontend/` 单页应用 + 独立 embed 挂件入口 | 类型检查与后端契约对齐有守卫 | 前端包名保留历史拼写，见 [§29](29-术语表.md) |
| **TDesign / marked / KaTeX / highlight.js / Mermaid** | 控制台 UI 与渲染 | 聊天流式渲染、公式、代码高亮、图渲染 | 纯前端依赖，无服务端配套 | xlsx 以本地 tgz 锁版本引入 |
| **@microsoft/fetch-event-source** | SSE 消费 | 控制台问答流的浏览器端实现 | 支持POST + 自定义头 | 断线续流语义依赖后端续流端点 |

> **依赖编排**：版本唯一来源是根 `pom.xml` 的 `<properties>` + `<dependencyManagement>`（Boot BOM 统一管理）；模块 pom 只声明依赖，不允许自带版本。`:contract` 的生产依赖块为空，契约纯度由编译期与守卫双重保证。
