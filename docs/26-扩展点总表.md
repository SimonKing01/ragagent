# 26. 扩展点总表

按"想加什么"归类的扩展入口。原则只有一个：**实现在能力模块或域内，契约在 `:contract`，装配在组合根或域内 Wiring**——大多数扩展不需要动 `:boot`。

| 想扩展什么 | 怎么扩展 | 现状 / 默认 |
|---|---|---|
| 跨模块端口 | 在 `:contract` 定义 `*Port`，实现侧唯一（ArchUnit 强制），登记 [architecture/port-map.md](architecture/port-map.md) | 41 个端口 |
| 业务域 | 在 `domains/` 新建根包 + `package-info.java`，登记 `scripts/capability-kinds.json` | 19 个域 |
| 装配点 | 新增 `@Configuration` 必须登记 `scripts/wiring-points.baseline.json`（组合根 / 域内 / 模块内三选一 + 理由） | 23 个装配点 |
| 配置属性类 | 落进 `@ConfigurationPropertiesScan` 白名单包；禁止裸读 `System.getenv` | 10 个白名单包 |
| 模块依赖边 | 改 `scripts/check-module-graph.py` 的矩阵需给理由；棘轮只许减 | 13 条主码边 |
| 新增路由 | 控制器注解登记角色下限（`RbacRoutePolicies`）+ API-Key 能力（`APIKeyRoutePolicies`），守卫强制进对照表 | 384 条路由 |
| LLM 提供商 | `ProviderName` 加枚举 + 实现 `Provider` + `ProviderRegistry` 注册；厂商特有参数再实现 `ProviderAdapter` | 26 家 |
| 嵌入 / 重排 provider | `EmbedderFactory` / `RerankerFactory` 的 provider 分支加一类 | 缺省回落 OpenAI 兼容实现 |
| 检索引擎 | `retrieval-engine` 实现 `RetrieveEngineRepository`，在 `EngineFactory.SPECS`、`EffectiveEngines`、`RetrievalEngineWiringConfig`、`VectorEngineTypes` 四处登记 | 9 种 |
| DB 向量库（租户自助） | 控制台注册（限可配置的 7 家），知识库绑定 `vector_store_id` | 未绑定走环境级引擎 |
| 租户检索参数 / 引擎路由 | `tenants.retrieval_config` / `tenants.retriever_engines` | 缺省取 `application.yml` 的 `conversation:` 段 |
| 实体关系抽取 | 实现 `EntityExtractionPort`（`contract/model/`） | `EntityExtractionAdapter`（model-runtime） |
| 入库文本来源 | `KnowledgeTextExtractor.extract` 加分支 | manual / docreader / 音视频 |
| 分块策略 | 实现 `Chunker`（分块域内），不动 worker 主流程 | — |
| 富化子任务 | `planFinalizing` 加计划项 + 子任务队列 + `pending_subtasks_count` 计数收口 | wiki / 图谱 / 问题生成 + 摘要旁路 |
| 外部数据源连接器 | 实现 `Connector`（或 `StreamingConnector`），在 `DataSourceWiring` 注册 + `ConnectorCatalog` 加元数据 | 9 个实现 |
| 管线插件 | 实现 `Plugin`（声明 `activationEvents`），在 `QaWiring` 按序注册；跑 `scripts/gen-pipeline-map.py` 与管线完整性测试 | 17 个插件 |
| 管线阶段 | `PipelineEventType` 加枚举值（完整性测试强制至少一个插件） | 14 个阶段 |
| 预设管线 | `PipelineBuilder.presets()` 加一条 | 5 个预设 |
| 内置业务工具 | 实现 `contract.tool.AgentTool`，在 `AgentToolBackends` 与装配 switch 各加一个分支（三方一致性守卫强制） | 22 个实现 / 33 个工具名常量 |
| 技能数据源 | 实现 `agent.skills.SkillSource` 传入技能目录装配 | 平台内置层 + 租户自建层 |
| MCP 传输 | 实现 `mcp.protocol.McpTransport` 并在客户端工厂接线（stdio 因命令注入风险硬禁用） | SSE / Streamable HTTP |
| IM 渠道适配器 | 实现 `im/runtime` 的适配器接口 + 工厂，在 `ImAdapterWiringConfig` 注册一行 | 9 渠道 |
| 流管理器后端 | 实现 `StreamManager`，在 `StreamManagerConfig` 加分支 | memory / redis 双实现 |
| 队列后端 | 五套队列各有进程内 + Redis 双实现，Wiring 按开关选择 | 见 [§20](20-异步任务队列与多实例协调.md) |
| 模型并发限流后端 | 实现 `ModelConcurrencyLimiter`，在 `ModelConcurrencyGovernorWiring` 装配 | 进程内 / Redis |
| thinking 编码策略 | 实现 `ThinkingStrategy` 或经 `extra_config.thinking_control` 选 4 策略之一 | `None` |
| 审计动作 | `contract` 审计常量加动作名，写 `AuditWritePort.logBestEffort` | 65 个动作常量 |
| SSRF 白名单条目 | env `SSRF_WHITELIST_EXTRA` 或系统设置运行期推送 | 空 = 全按黑名单 |
| 含凭据的 jsonb 列 | 挂 `SecretJsonTypeHandler`（键名含 secret/apikey/token 等自动命中） | 明文 |
| 架构守卫 | `scripts/run-guards.sh` 加一行 `run`（自计数）；棘轮基线进 `*.baseline.json` | 48 条守卫 |
| 前端 locale | `frontend/src/i18n/locales/` 加语言包并注册，过 i18n 审计 | 7 个 |

> **加一个能力的完整动线**（以"新增一种富化子任务"为例）：契约（如需跨域）→ 域内实现 → 队列接口加双实现 → `planFinalizing` 计划项 → 计数收口 → `package-info.java` 写四要素 → 跑 `mvn -B verify` 让守卫校验登记面。大多数步骤是"登记"而非"编码"。
