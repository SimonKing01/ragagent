# 21. 可观测性与运维

## 21.1 起服能力摘要

`StartupCapabilityReport`（`boot/.../config/`，开关 `ragagent.capability-report.enabled` 缺省开）在启动期打一行 `[capabilities]` 摘要：`retrieval=<driver|OFF> engines=<N> | jwt=<env|RANDOM> | storage=<本地目录> | redis=<host:port|(unreachable)> | stream=<redis|memory>`。它不改变行为，只把"静默降级"变得可见，降级信号以 WARN 单独打印：

- `[capabilities] RETRIEVE_DRIVER 为空：检索引擎关闭，问答不会带知识库上下文`；
- `[capabilities] RETRIEVE_DRIVER=... 但未注册任何引擎`；
- `[capabilities] JWT_SECRET 未设置：本次进程随机生成，重启后所有登录态失效`。

存储目录不可写则直接抛异常拒绝启动（写探针文件）。另有 `[builtin-models]`（`BuiltinModelsReconciler`，内置模型清单回填，WARN 逐条报告跳过的非法条目）等启动日志。

## 21.2 Actuator 与自定义指标

`management.endpoints.web.exposure.include: health,info,metrics`——只暴露三个端点，`env/beans/heapdump` 等敏感端点不暴露；`health.show-details: never`。**鉴权口径**：三个端点都不在 `AuthFilter` 的 noAuth 白名单里（白名单只有 `/health`），因此匿名访问 401、携带有效登录态 200。

自定义 Micrometer 指标（全仓 `ragagent.` 前缀经 `Metrics.counter` 静态注册的共 3 个，均为问答轮次计数）：

| 指标 | 标签 | 记录点 |
|---|---|---|
| `ragagent.qa.turns` | `mode` | `QaTurnExecutor`（一轮问答开始） |
| `ragagent.qa.failures` | `mode` | `QaTurnExecutor`（轮次失败） |
| `ragagent.qa.terminal` | `mode` + `outcome`（done/failed/cancelled 等） | `QaTerminalMetrics`（仅 `TurnLifecycle.finish` 赢家调用，天然不重复计数） |

## 21.3 追踪：OTLP 与 Langfuse

追踪栈在 `platform/.../tracing/`：自实现 span/trace 载体（`Span` / `Trace` / `LangfuseContext`）+ OTLP 导出器 `OtlpHttpExporter`（OTel protobuf 编码，proto 定义 vendored 在仓库根 `otlp-proto/opentelemetry/proto/`）+ 内存队列批刷 `BatchSpanProcessor`（`flushAt` 缺省 15、间隔缺省 3000ms、队列 2048）。配置全部来自 `LANGFUSE_*` env（`LangfuseEnvProperties` → `LangfuseConfig.fromEnv`）：

- **未配置** → 自动禁用，`NoopLangfuseManager` 单例零成本，启动打 `[Langfuse] disabled (no LANGFUSE_PUBLIC_KEY/SECRET_KEY)`；
- **显式启用但配置无效**（缺 host 或密钥对不全）→ `LangfuseWiring` 的 `@PostConstruct` 抛异常**拒绝启动**；
- 有 `LANGFUSE_PUBLIC_KEY` + `LANGFUSE_SECRET_KEY` 且未显式禁用 → 自动启用（与 Python SDK 口径一致）。

接入点：请求级由 `LangfuseHttpInterceptor`（order=10，在门禁之后——被 RBAC/API-Key 拒绝的请求不产生 trace）；模型调用由装饰器 `LangfuseChatClient` / `LangfuseEmbedder` / `LangfuseReranker` / `LangfuseVlm`（`platform/.../tracing/decorators/`）携带生成式负载；异步任务经 `TraceInjector` 把 trace 上下文注入任务载荷（业务域不直连厂商实现）。dev 自建栈 `docker-compose.langfuse.yml`（clickhouse + worker + web + S3，UI `:3000`），预置密钥写进 `.env`。请求关联：`RequestIdFilter`（order=`HIGHEST_PRECEDENCE+10`）生成/透传 `X-Request-ID`，写入 MDC 与 `TenantContext.setRequestId`（快照随之跨线程）。

## 21.4 日志关键字

以下关键字均已在源码核实（括号内为代表类）：

| 关键字 | 含义 |
|---|---|
| `[capabilities]` | 起服能力摘要与降级 WARN（`StartupCapabilityReport`） |
| `[PIPELINE] stage=...` | 管线阶段推进（`PipelineLog` 等） |
| `[Agent]` / `[Agent][Round-N]` | Agent 循环开始/轮次/取消与某轮上下文（`agent-engine` 的 `ReActIteration` / `ThinkPhase` 等） |
| `[QA]` | 轮次收尾与落库（`QaTurnFinalizer`） |
| `[KnowledgeProcess]` / `[KnowledgePostProcess]` | 文档摄取与富化 fan-out（`knowledge/task` 各阶段） |
| `[session-read-miss]` / `[session-read-forbidden]` | 会话可见性判定，排查"为什么 404"（`SessionService`） |
| `[auth]` / `[rbac]` / `[ssrf-whitelist]` / `[crypto]` / `[Langfuse]` / `[builtin-models]` | 认证装配 / RBAC 拒绝 / 白名单条目丢弃 / 解密失败 / 追踪开关 / 内置模型回填 |

## 21.6 启动期任务回收 `StartupTaskRecovery`

`ApplicationReadyEvent` 时把"重启前卡在处理态"的任务复位为 failed，避免前端永远转圈（失败只 WARN，不阻塞启动）：

1. **知识解析**：`parse_status ∈ {pending, processing, finalizing, deleting}` → `failed`，文案 `Task interrupted due to application restart`；仅单机形态跑（`knowledge.redis-enabled=false`）——分布式下另一副本可能在处理同一知识，启动钩子不敢判死；复位成功后按行取消孤儿 span（errorCode=`SERVER_RESTART`）；
2. **摘要生成**（Lite 路径）：`summary_status ∈ {pending, processing}` → `failed`；
3. **数据源同步日志**：`sync_logs.status='running'` → `failed` + `Sync interrupted due to application restart`；分布式模式加 **30 分钟陈旧窗**（持久化队列里可能有未开 span 的积压任务，只有明显陈旧的才敢判死）；
4. 顺带重试至多 200 条失败的知识删除清理。

## 21.7 排障速查：现象 → 先看什么

| 现象 | 先看 |
|---|---|
| 起服后"活着但什么都不能干" | 启动日志 `[capabilities]` 的 WARN 行（retrieval OFF / engines=0 / jwt RANDOM） |
| 请求 404 / 401 | 路由是否白名单/成员；`[session-read-miss]` / `[session-read-forbidden]`；`[auth]` 装配日志 |
| 角色够但 403 | `docs/architecture/route-policy-map.md` 对照下限；`[rbac]` WARN 与 `rbac.access_denied` 审计；是否栽在第二层（所有权/API Key 范围） |
| 有回答但没有引用 | `[capabilities]` 的 `retrieval=` / `engines=`；`[PIPELINE] stage=chunk_search` 阶段日志 |
| 回答卡住不结束 | `AgentStreamBridge` 是否收到 `complete`；`StreamManager` 是否还有事件 |
| 中途断流 | `SseFrameWriter.write` 的 `IOException`（客户端断开靠写失败检测） |
| 消息没落库 | `QaTurnFinalizer` 的提交/回滚日志（`[QA]`） |
| 工具调用失败 | `[Agent][Round-N]` + 工具名；MCP 服务是否可达（SSRF 拒绝看 `SsrfException` 文案） |
| IM/embed 消息不回复 | 渠道是否禁用；wss 是否被旧版 scheme 白名单挡（现已放行）；`[ssrf-whitelist]` 是否丢条目 |
