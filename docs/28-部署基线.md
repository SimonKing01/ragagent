# 28. 部署基线

## 28.1 本地基础设施（docker-compose）

`docker-compose.yml` 起 3 个 dev 容器（外部网络 `weknora_WeKnora-network-dev`，compose 项目名带前缀）：

| 服务 | 镜像 | 宿主端口 | 说明 |
|---|---|---|---|
| `postgres` | `paradedb/paradedb:v0.22.2-pg17` | 15432 | 自带 pgvector + ParadeDB BM25（`RETRIEVE_DRIVER=postgres` 的依赖） |
| `redis` | `redis:7.0-alpine` | 16379 | dev 无密码 |
| `docreader` | `wechatopenai/weknora-docreader:latest` | 50051 | 文档解析 gRPC（上游 WeKnora 命名的历史沿用） |

`docker-compose.langfuse.yml` 是 dev 专用的 Langfuse v3 自建栈（`clickhouse` + `rustfs` S3 + `worker` + `web`，UI 3000 端口，PostgreSQL/Redis 复用 dev 容器），配合 `:platform` 的 `LANGFUSE_*` 追踪配置使用，与生产无关。

## 28.2 服务镜像

- **根 `Dockerfile`**（进 CI 的 `docker` job）：两阶段——`maven:3.9-eclipse-temurin-21` 构建出 `boot/target/boot-0.0.1-SNAPSHOT.jar`，`eclipse-temurin:21-jre` 运行。`WORKDIR /app`；`COPY --from=builder /build/migrations/versioned ./build/generated-migrations/` 把 Flyway 迁移落到**相对工作目录**的 `/app/build/generated-migrations`——这正对上 `application.yml` 里 `filesystem:./build/generated-migrations` 的声明，漏拷则全新容器启动无 schema 且 Flyway 静默不报错。非 root 用户 `ragagent` 运行，`EXPOSE 8080`，`HEALTHCHECK` 打 `/health`，`ENTRYPOINT` 带 `-XX:MaxRAMPercentage=75`。
- **`deploy/Dockerfile.app`**：生产后端镜像——jar 与迁移目录由 `deploy/build-images.sh` 在本机（arm64 → `linux/amd64`）打好后 COPY 进来，不在容器内跑 Maven；额外装 `ffmpeg`（音视频入库），其余语义与根 Dockerfile 的运行阶段一致。
- **`deploy/Dockerfile.ui`**：前端镜像——本机构建的 `dist` + nginx 固定摘要镜像（`nginx:1.30.3-alpine@sha256:…`），模板经 envsubst 注入 `APP_HOST`/`APP_PORT` 后反代后端。
- **`deploy/Dockerfile.ocr`**：RapidOCR 纯 CPU 服务（`GET /health`、`POST /ocr`），暴露 18092；构建 context 必须是仓库根（要拷 `scripts/ocr-server.py`）。
- **`deploy/build-images.sh`**：`VERSION=<git sha>` 全量构建后端 jar + 前端 dist（含 `.gz` 预压缩）并出两个镜像 tag；`--save` 导出 `deploy/.build/images.tar.gz` 供服务器 `docker load`（服务器不构建）。
- **`deploy/docker-compose.prod.yml`**：单机生产编排——`postgres`/`redis`/`ocr`/`docreader`/`app`/`frontend` 六服务；前端只绑 `127.0.0.1:8000` 由宿主 nginx 反代，后端不出网；`DB_PASSWORD`/`SYSTEM_AES_KEY`/`JWT_SECRET` 用 `${VAR:?}` 强制必填；`app` 挂 `data-files` 卷到 `/app/data/files` 并限内存 1200m。
- **`deploy/env.prod.example`**：服务器端 `.env` 模板（敏感项 `openssl rand` 现生成），额外定义 `APP_VERSION`/`UI_VERSION`/`OCR_VERSION` 与 `APP_EXTERNAL_URL`——后者把 `local://` 引用签成可外链的 `/r/{token}`，IM 渠道发图依赖它。

## 28.3 生产必改清单

| 项 | 为什么 | 不改的后果 |
|---|---|---|
| 固定 `JWT_SECRET` | 不设则每次启动随机生成 32 字节 | 重启后全员掉登录；多实例间 token 互不认 |
| 设置 `SYSTEM_AES_KEY`（恰 32 字节） | 模型凭证加密/临时文档/租户隔离共用；建库后不可轮换 | 非 32 字节视为未配置；解析已加密数据抛 `IllegalStateException`，换 key 则旧密文不可解 |
| `LOCAL_STORAGE_BASE_DIR` 挂持久卷 | 容器缺省落在 `/app/data/files`（compose 已挂 `data-files` 卷） | 不挂卷则容器重建丢已入库文档的原始文件 |
| 显式 `RETRIEVE_DRIVER` | 为空 = 检索引擎整体关闭 | 问答拿不到知识库上下文且**不报错**，静默降级 |
| 多实例打开 Redis 开关 | 见 [§28.4](28-部署基线.md)；各开关缺省走进程内实现 | 多副本各自为政：重复执行、限流失真、跨实例 stop 失效 |
| SSRF 白名单 | `SSRF_WHITELIST`/`SSRF_WHITELIST_EXTRA` 与 DB 设置 `ssrf.whitelist` 控制出站目标 | 自建 LLM/MCP/连接器域名被 SSRF 防护拦截 |
| `SPRINGDOC_ENABLED=false` | API 文档面（`/scalar`、`/v3/api-docs`）默认关 | 打开会向未认证面之外的访客暴露接口结构 |
| 修改 `DB_PASSWORD` | dev 缺省 `postgres123!@#` 写在 yml/`.env.example` | 弱口令随示例入库 |

## 28.4 多实例部署注意

单实例缺省语义是"进程内一切"：SSE 流管理器（`STREAM_MANAGER_TYPE=memory`）、模型并发闸门（进程内信号量）、embed 限流（进程内滑窗）、wiki/knowledge/memory/datasource/im 各域队列与锁（进程内）全部不走 Redis。扩到多实例时按需打开 [§22.3](22-配置体系.md) 的开关组：`STREAM_MANAGER_TYPE=redis`（断线续流必须，否则 SSE 事件只在原进程）、`LLM_LIMITER_REDIS_ENABLED`、`EMBED_REDIS_ENABLED`、以及各域 `*_REDIS_ENABLED`（队列共享 + 崩溃回收重投；datasource 还有按 `(dataSourceID, 分钟)` 的确定性 TaskID 去重，cron 同分钟多副本同触只有第一个赢）。每个开关启动 ping Redis、连不上即拒启。

全仓主码**没有一处 `@Scheduled`**（已核实为 0）：周期同步等调度由域内自管的 `ThreadPoolTaskScheduler` 承担（如 `domains` 数据源域的 `Scheduler`），配合队列租约与去重实现多副本安全——这是"调度不依赖 Spring 注解、把并发正确性压在队列层"的刻意取舍。系统设置（`system_settings`）在多副本下是每请求直读 DB、无跨副本失效广播：本副本 UI 改动不再即时广播给对端（`SystemSettingService` 明示的单实例语义边界）。

## 28.5 健康检查与冒烟

- **`GET /health`**（`platform` 的 `HealthController`）：返回 `{"status":"ok"}`，在 `AuthFilter` 的无鉴权白名单里（仅 GET），且不进统一响应外壳——供 docker `HEALTHCHECK`、k8s 探针与外部监控使用。它只证明 Spring 上下文已就绪，**不证明数据库连通**（存活 ≠ 就绪）。
- **`/actuator/health`**：actuator 只暴露 `health,info,metrics` 且 `show-details: never`；`/actuator/**` **不在** `AuthFilter` 白名单内，未带 JWT/API-Key 一律 401——区别于 `/health` 的无鉴权。监控打 `/health`，需要带凭据的细节检查才走 actuator。
- **CI 启动冒烟**（`scripts/ci-smoke.sh`，backend job 在真实打包 jar 上执行，非 MockMvc）：① `/health` 返回 200（Flyway、数据源真的起来了）；② 默认关闭 Swagger 时 `/v3/api-docs` 返回 404；③ 进程能被正常停掉。镜像构建另有独立 `docker` job 兜住根 `Dockerfile` 的路径腐化。
